# 网站定位、需求分析与内容管理规划

> 版本：v0.1  
> 日期：2026-06-02  
> 目标：先明确方向、审美、需求、工具链和内容管理方式，再进入功能实现。

---

## 1. 一句话定位

这是一个面向长期成长的个人数字空间，不是单纯博客，也不是纯文档站。

它应该同时承载：

- 知识库沉淀：技术文档、学习笔记、架构记录、踩坑复盘。
- 项目展示：项目作品、工程案例、软硬件实现、成果展示。
- 个人风采：摄影、生活、经历、审美、成长轨迹。
- 趣味互动：有记忆点的小实验、小游戏、菜单动效、彩蛋入口。

推荐定位语：

> 一个兼具飞书式知识库秩序、工程师作品集表达和个人生活审美的数字工作台。

---

## 2. 审美需求

### 2.1 核心审美方向

整体审美应是：

> 飞书式清晰文档体验 + 个人科技感网页 + 少量互动惊喜。

飞书式体验强调清晰、稳定、可读、层级明确；当前网站已有空间、科技、玻璃、动效、个人表达，不能被完全抹掉。最终效果应该像“文档能力自然长在这个个人站里”，而不是外接一个风格割裂的文档系统。

### 2.2 关键词

- 清爽：正文阅读不被背景和动效打扰。
- 高级：少用花哨装饰，靠间距、层级、字体、留白、质感建立高级感。
- 统一：知识库、项目、个人分享、互动入口都使用同一套视觉语言。
- 可读：正文页优先保障阅读体验。
- 有辨识度：保留工程师、嵌入式、航天/科技、摄影等个人标签。

### 2.3 页面审美分层

不同模块不应该一刀切：

- 首页：可以更有视觉冲击和互动感，用来建立第一印象。
- 知识库：最克制，优先阅读效率，对标飞书/语雀/Notion 的信息秩序。
- 项目页：介于文档和作品集之间，需要图文叙事、案例感、成果感。
- 个人分享：可以更有照片、情绪、生活感。
- 趣味实验室：允许更活泼，但要作为次级入口，不干扰主线。

## 3. 核心需求分析

### 3.1 知识库沉淀

目标：让网站成为长期技术积累的地方。

需要支持：

- 按主题分类：嵌入式、前端、系统设计、调试记录、工具链、竞赛笔记。
- 按文章层级组织：系列、章节、单篇。
- 支持 Markdown 编辑。
- 支持标题目录自动生成。
- 支持标签、更新时间、阅读时长、难度等级。
- 支持搜索。
- 支持代码块、图片、表格、链接、任务清单。

推荐文章类型：

- 技术笔记：记录知识点和学习过程。
- 架构文档：记录项目架构、模块边界、通信协议。
- Bug 复盘：问题现象、定位过程、根因、修复方案、预防措施。
- 开发日志：项目阶段性进展和决策记录。
- 工具指南：环境搭建、部署、脚本、常用命令。

### 3.2 项目展示

目标：让项目从“卡片展示”升级成“案例作品”。

每个项目建议包含：

- 项目背景：为什么做。
- 项目目标：要解决什么问题。
- 技术栈：硬件、软件、协议、框架。
- 系统架构：模块图、数据流、通信关系。
- 核心功能：3 到 5 个重点能力。
- 实现过程：关键难点和解决方案。
- 成果展示：截图、照片、演示视频/GIF。
- 复盘总结：做得好的地方、遗留问题、下一步优化。

项目页需要更像作品集案例，而不是单纯文档。

### 3.3 个人风采展示

目标：保留人的部分，让网站不是“冷冰冰的技术仓库”。

内容可以包括：

- 摄影作品。
- 生活记录。
- 比赛/活动经历。
- 桌面、装备、工作流。
- 阶段性成长总结。
- 一些不那么正式但有审美的短文。

个人分享页不应该承担严肃知识库的全部信息密度，可以更注重图片和情绪。

### 3.4 趣味互动与菜单

目标：形成网站记忆点。

可保留或扩展：

- 首页导航舞台。
- 趣味实验室。
- 小游戏。
- 小宠物。
- 彩蛋入口。
- 动态菜单。
- 留言板互动。

原则：

- 互动服务于探索，不压过内容。
- 动效只用在入口、反馈、状态变化上。
- 文档阅读页尽量少动效。

## 4. 信息架构规划

### 4.1 一级导航建议

建议保留 5 到 6 个主入口：

1. 首页
2. 知识库
3. 项目作品
4. 个人分享
5. 趣味实验室
6. 留言板

首页是入口，不应塞满全部内容；真正的内容沉淀在知识库、项目作品和个人分享里。

### 4.2 知识库结构

推荐目录：

```text
docs-vitepress/
  docs/
    index.md
    embedded/
      stm32-notes.md
      freertos-notes.md
    frontend/
      vite-typescript.md
    system-design/
      architecture-overview.md
    debugging/
      serial-debug.md
      build-errors.md
```

当前项目还没有嵌套读取能力，后续要规划支持“多级知识树”。短期可以先保持单层文件，长期再升级到多级目录。

### 4.3 项目结构

推荐目录：

```text
docs-vitepress/
  projects/
    index.md
    edge-gateway.md
    motor-control.md
    smart-car.md
```

每个项目一个 Markdown 文件，frontmatter 负责卡片信息，正文负责详情页。

### 4.4 个人分享结构

推荐目录：

```text
docs-vitepress/
  life/
    index.md
    street-light.md
    mountain-weekend.md
    desk-upgrade.md
```

后续如果个人内容变多，可以再分：

```text
life/
  photography/
  daily/
  competition/
  setup/
```

## 5. 内容模型规划

### 5.1 技术文档 frontmatter

建议格式：

```yaml
---
id: architecture-overview
title: Architecture Overview
category: System Design
tags:
  - Architecture
  - Frontend
level: beginner
createdAt: '2026-04-01'
updatedAt: '2026-06-02'
readingTime: 10 min
views: 0
summary: Overview of the embedded blog architecture and extension mechanism.
cover: /images/docs/architecture-cover.jpg
status: published
---
```

字段说明：

- `id`：路由和唯一标识，不要随便改。
- `title`：展示标题。
- `category`：文档分类。
- `tags`：搜索和筛选标签。
- `level`：难度，建议 `beginner | intermediate | advanced`。
- `createdAt` / `updatedAt`：创建和更新日期。
- `readingTime`：阅读时长，可手写，后续可自动计算。
- `summary`：卡片摘要和搜索摘要。
- `cover`：可选封面。
- `status`：后续可支持 `draft | published | archived`。

### 5.2 项目 frontmatter

建议格式：

```yaml
---
id: edge-gateway
title: Industrial Edge Gateway
summary: ESP32 + FreeRTOS based industrial edge gateway.
stack:
  - ESP-IDF
  - FreeRTOS
  - MQTT
  - Modbus
highlights:
  - Auto reconnect
  - Offline cache
  - Remote logging
gallery:
  - /images/projects/edge-gateway/cover.jpg
  - /images/projects/edge-gateway/architecture.png
links:
  - label: GitHub
    href: https://github.com/example/example
role: Embedded Developer
period: '2026'
status: completed
---
```

项目正文建议模板：

```markdown
# 项目标题

## 项目背景

## 项目目标

## 系统架构

## 技术栈

## 核心功能

## 难点与解决方案

## 成果展示

## 复盘总结
```

### 5.3 个人分享 frontmatter

建议格式：

```yaml
---
id: street-light
title: Night Street Photography Practice
date: '2026-02-01'
tag: Photography
summary: A night street photography practice.
cover: /images/life/street-light/cover.jpg
mood: quiet
status: published
---
```

个人分享正文可以更自由，但建议至少有：

- 开头图片或封面。
- 事情背景。
- 过程记录。
- 感受或复盘。

## 6. 当前部署方式与内容管理方式

### 6.1 当前部署方式

当前项目是 Vite 静态站：

- 开发：`npm run dev`
- 构建：`npm run build`
- 预览：`npm run preview`
- GitHub Pages 部署：`npm run deploy`，依赖 `gh-pages -d dist`
- Gitee Pages 部署：`deploy-gitee.ps1` 会进入 `dist` 并推送到 Gitee 的 `gh-pages`
- Vite base：`/embedded-blog/`
- 线上地址配置：`https://www223.gitee.io/embedded-blog/`

这意味着网站最终部署的是 `dist/` 里的静态文件。所有内容在部署前都应该先被构建进静态资源。

### 6.2 当前可编辑内容分布

当前项目存在几类内容源：

```text
docs-vitepress/        更适合维护 Markdown 正文和 frontmatter
src/content/           当前页面读取的数据层
content/               YAML/JSON 旧内容源或备用内容源
public/                图片、背景、favicon 等静态素材
src/features/          页面功能和互动逻辑
src/styles/            视觉样式
scripts/               内容生成、添加卡片、调试脚本
```

为了方便长期管理，建议建立明确规则：

> 你平时主要编辑 `docs-vitepress/` 和 `public/`。  
> 尽量不要直接编辑 `src/content/` 中的大段正文。  
> `src/content/` 应该逐步变成由脚本生成或自动导入的索引层。

### 6.3 推荐的日常编辑流程

#### 修改一篇技术文档

1. 打开 `docs-vitepress/docs/xxx.md`
2. 修改 frontmatter 中的标题、标签、更新时间、摘要。
3. 修改正文 Markdown。
4. 如果用到图片，把图片放到 `public/images/docs/xxx/`。
5. 在 Markdown 中用 `/images/docs/xxx/image.png` 引用。
6. 本地运行 `npm run dev` 预览。
7. 构建并部署。

#### 新增一个项目

1. 在 `docs-vitepress/projects/` 新建 `project-id.md`。
2. 按项目 frontmatter 模板填写元信息。
3. 把项目图片放到 `public/images/projects/project-id/`。
4. 正文按“背景、目标、架构、难点、成果、复盘”写。
5. 确认项目列表能读取到该文件。
6. 本地预览。
7. 构建部署。

#### 新增一篇个人分享

1. 在 `docs-vitepress/life/` 新建 `post-id.md`。
2. 填写 `title/date/tag/summary/cover`。
3. 图片放到 `public/images/life/post-id/`。
4. 正文自由写作。
5. 本地预览。
6. 构建部署。

#### 替换背景或头像

1. 图片放到 `public/images/site/` 或保留当前 `public/` 根目录。
2. 修改对应 CSS 或页面配置。
3. 优先使用语义化命名，例如：

```text
public/images/site/home-space-bg.jpg
public/images/site/docs-light-bg.jpg
public/images/site/docs-dark-bg.jpg
public/images/profile/avatar.jpg
```

### 6.4 需要补强的内容管理能力

当前管理方式还不够顺手，后续建议做这些增强：

1. **统一内容源**
   - 以 `docs-vitepress/*.md` 为唯一主内容源。
   - `src/content/*.ts` 只做索引，不手写大段正文。

2. **自动扫描 Markdown**
   - 使用 `import.meta.glob` 或内容生成脚本扫描 `docs-vitepress/docs|projects|life`。
   - 自动解析 frontmatter 和正文。
   - 新增文章后不必手动改 `src/content/*.ts`。

3. **修复生成脚本**
   - 现有 `scripts/generate_content.py` 可以读取 VitePress Markdown，但会生成 TS 字符串。
   - 后续应改成生成轻量索引，或直接取消生成步骤。

4. **新增内容脚手架**
   - 提供命令创建新文档、新项目、新生活文章。
   - 自动生成 `.md` 模板和图片目录。

5. **素材目录规范**
   - 建立 `public/images/docs/`、`public/images/projects/`、`public/images/life/`、`public/images/site/`。

6. **内容状态**
   - frontmatter 支持 `draft/published/archived`。
   - 草稿不进入线上列表。

7. **搜索索引**
   - 小规模先用 Fuse.js。
   - 文档多了以后用 Pagefind 生成静态全文索引。

## 7. 工具链采集与取舍

### 7.1 当前工具链

| 工具 | 当前作用 | 是否保留 |
| --- | --- | --- |
| Vite | 主站构建与开发服务器 | 保留 |
| TypeScript | 类型约束与模块化 | 保留 |
| GSAP | 动效 | 保留但控制使用范围 |
| Zod | 内容 schema 校验 | 保留 |
| VitePress | 文档源/独立文档站潜力 | 保留并吸收其内容组织方式 |
| gh-pages | GitHub Pages 部署 | 保留 |

### 7.2 建议补充工具

| 工具 | 适用阶段 | 作用 | 取舍 |
| --- | --- | --- | --- |
| markdown-it | 内容系统升级 | Markdown 渲染和插件扩展 | 可选，VitePress 已内置相关能力 |
| gray-matter | 内容系统升级 | 解析 Markdown frontmatter | 推荐 |
| Shiki | 技术文档增强 | 高质量代码高亮 | 推荐 |
| Fuse.js | 初期搜索 | 轻量模糊搜索 | 推荐短期使用 |
| Pagefind | 大规模知识库 | 静态全文搜索索引 | 推荐中后期使用 |
| PhotoSwipe | 图片展示 | 项目截图/摄影灯箱 | 推荐用于项目和个人分享 |
| pnpm/npm scripts | 内容管理 | 新增、生成、检查、部署命令 | 推荐 |

### 7.3 工具链原则

- 不为了工具而工具。
- 当前主站保持 Vite + TypeScript。
- 内容编辑体验优先 Markdown。
- 搜索先轻量，内容变多后再上 Pagefind。
- 图片灯箱等增强应先服务项目和摄影页。
- 动效保留个人特色，但文档页要克制。

## 9. 页面规划

### 9.1 首页

目标：建立第一印象和导航入口。

内容：

- 个人身份：嵌入式工程师 / 摄影 / 创作者。
- 四个主入口：知识库、项目作品、个人分享、趣味实验室。
- 少量动态效果。
- 不做过长介绍，不变成营销页。

### 9.2 知识库列表页

目标：快速找到文档。

需要：

- 分类筛选。
- 标签筛选。
- 搜索。
- 最近更新。
- 推荐/置顶文档。
- 文档卡片信息：标题、摘要、分类、标签、更新时间、难度。

### 9.3 知识库详情页

目标：飞书式阅读体验。

需要：

- 左侧知识树。
- 中间正文。
- 右侧目录。
- 阅读进度。
- 代码高亮。
- 图片自适应。
- 上一篇/下一篇。
- 相关文档。

### 9.4 项目列表页

目标：展示作品能力。

需要：

- 项目分类：嵌入式、前端、实验、竞赛。
- 技术栈筛选。
- 项目卡片突出图片、成果和技术栈。
- 可以区分已完成、进行中、实验性质。

### 9.5 项目详情页

目标：作品集案例页。

需要：

- 项目封面和摘要。
- 技术栈、角色、时间、状态。
- 架构图。
- 功能亮点。
- 难点复盘。
- 图集灯箱。
- 相关链接。

### 9.6 个人分享页

目标：展示人的状态和审美。

需要：

- 摄影/生活/成长/装备等分类。
- 图片更重要，文字更自由。
- 列表页不要太像技术卡片。
- 详情页可以偏图文杂志感。

### 9.7 趣味实验室

目标：网站记忆点。

可包含：

- 小游戏。
- 反应测试。
- 小宠物。
- 彩蛋。
- 动效菜单实验。

原则：趣味实验室可以活泼，但入口和主站风格仍需统一。

## 10. 迭代路线

### 阶段 0：规划和内容盘点

目标：明确方向，不动手乱改。

任务：

- 确认本规划。
- 盘点已有 Markdown、YAML、图片和旧文档。
- 标记哪些内容要保留、重写、删除、迁移。
- 修复或替换乱码文档。

### 阶段 1：内容源统一

目标：让你能方便编辑内容。

任务：

- 以 `docs-vitepress` Markdown 为主内容源。
- 统一 frontmatter。
- 支持自动扫描文档。
- 建立素材目录规范。
- 改造/替换 `generate_content.py`。
- 新增创建内容的脚手架命令。

验收：

- 新增一篇 Markdown 后，不需要手动写 TS 字符串。
- 图片引用路径清晰。
- 本地预览能看到新内容。

### 阶段 2：知识库体验

目标：对标飞书文档体验。

任务：

- 左侧知识树。
- 右侧目录。
- 正文排版。
- 代码高亮。
- 搜索。
- 相关文档。
- 移动端适配。

验收：

- 长文阅读不累。
- 目录自动生成。
- 文档树能反映内容分类。
- 搜索能找到标题、摘要、正文关键词。

### 阶段 3：项目作品升级

目标：让项目页从卡片变成案例。

任务：

- 项目详情模板。
- 图片画廊。
- 架构图区域。
- 难点复盘模块。
- 项目状态和技术栈筛选。

验收：

- 每个项目可以讲清楚背景、实现、成果和复盘。
- 图片展示专业。
- 技术栈和亮点易扫读。

### 阶段 4：个人风采和素材体系

目标：让网站有人的温度。

任务：

- 摄影/生活页视觉增强。
- 个人资料区。
- 头像、照片、经历素材整理。
- 图文详情页模板。

验收：

### 阶段 5：趣味互动收束

目标：保留趣味但不杂乱。

任务：

- 梳理现有小游戏和小宠物。
- 统一实验室入口。
- 精简过度干扰阅读的动效。
- 增加少量有意义彩蛋。

验收：

- 趣味入口明确。
- 主线内容不被干扰。
- 用户能感受到个人特色。

## 11. 当前优先级建议

近期不要先继续堆页面，而应该先做：

1. 确认本规划。
2. 修复内容编码和乱码问题。
3. 统一 Markdown 内容源。
4. 设计三类内容模板：技术文档、项目、个人分享。
5. 整理 `public/` 素材目录。
6. 再开始优化页面和交互。

最重要的一句话：

> 先让内容可维护，再让页面更漂亮；否则后续每次改文档和项目都会很痛苦。

## 12. 成功标准

这个网站阶段性成功，应满足：

- 你能在 5 分钟内新建一篇文档草稿。
- 你能在 10 分钟内新增一个项目卡片和项目详情骨架。
- 你不需要直接在 TS 字符串里写长文。
- 文档页阅读体验接近飞书：左侧树、中间正文、右侧目录。
- 项目页能体现工程能力和成果。
- 个人分享页能体现审美和生活状态。
- 趣味互动有记忆点，但不影响阅读。
- 构建部署流程清晰：编辑内容 -> 本地预览 -> 构建 -> 部署到 Pages。
