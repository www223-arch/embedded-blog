# 内容资产盘点与迁移清单

> 版本：v0.1  
> 日期：2026-06-02  
> 目标：把现有文档、项目、个人分享、图片素材、脚本和部署相关内容梳理清楚，明确哪些保留、迁移、修复、归档，以及以后如何方便维护网页内容。

---

## 1. 当前结论

当前项目里已经有内容系统的雏形，但内容源分散：

- `docs-vitepress/`：Markdown + frontmatter，最适合作为未来主内容源。
- `src/content/`：当前网页运行时读取的数据层，适合做索引层，不适合长期手写大段正文。
- `content/`：旧 YAML/JSON 内容源，适合作为迁移参考，后续应归档或合并。
- `docs/`：项目内部说明文档，其中部分中文存在乱码，需要重写或修复。
- `public/`：所有图片和静态资源，目前集中在根目录，命名和归类需要整理。
- `scripts/`：已有内容生成脚本，但部分脚本还在按旧模式写 TS 数据，后续需要改造。

核心迁移方向：

> 以 `docs-vitepress/*.md` 作为唯一主内容源，以 `public/images/...` 作为素材源，以 `src/content` 作为自动索引或轻量运行时数据层。

当前文件：

```text

```

处理策略：

| 文件 | 当前作用 | 处理建议 |
| --- | --- | --- |
| `schema.ts` | Zod schema 校验 | 保留，后续扩展字段 |
| `docs.ts` | 技术文档数据 | 过渡期保留，长期改为自动扫描 Markdown |
| `projects.ts` | 项目数据 | 过渡期保留，长期改为自动扫描 Markdown |
| `lifePosts.ts` | 个人分享数据 | 过渡期保留，长期改为自动扫描 Markdown |

不建议你长期直接编辑 `src/content/*.ts`。这些文件应该逐渐变成“由 Markdown 生成或自动导入”的运行时索引。

## 3. 迁移分级

### P0：先确认规则，不迁移文件

目标：避免乱动。

要做：

- 确认 `docs-vitepress` 是主内容源。
- 确认 `public/images` 是未来素材目录。
- 确认 `src/content` 不再作为手写长文入口。
- 确认旧 `content/` 暂时不删，只作为参考。

### P1：内容字段统一

目标：让 Markdown frontmatter 足够完整。

要做：

- 对比 `content/*.yaml/json` 和 `docs-vitepress/*.md` 的字段。
- 把缺失字段补进 `.md` frontmatter。
- 技术文档、项目、个人分享分别统一模板。
- 修复明显乱码正文。

### P2：内容读取方式统一

目标：新增内容不用改 TS。

推荐方案：

- 使用 `import.meta.glob` 扫描 `docs-vitepress/docs/**/*.md`、`projects/**/*.md`、`life/**/*.md`。
- 使用 frontmatter 生成列表卡片。
- 详情页直接渲染 Markdown 正文。
- `src/content` 仅保留 schema、类型、转换函数。

备选方案：

- 保留 `scripts/generate_content.py`，但改成生成索引文件，不把正文塞进 TS 字符串。

### P3：素材目录迁移

目标：图片命名和归档清晰。

要做：

- 建立 `public/images/...` 目录。
- 按 site/profile/docs/projects/life 分类迁移。
- 修改 Markdown 和 CSS 引用路径。
- 确认页面正常渲染。
- 旧根目录图片验证后再清理。

### P4：内容管理脚手架

目标：你以后新增内容更方便。

建议命令：

```bash
npm run new:doc
npm run new:project
npm run new:life
npm run check:content
```

预期效果：

- 自动询问或接收参数：标题、id、分类。
- 自动创建 `.md`。
- 自动创建图片目录。
- 自动生成 frontmatter 模板。
- 自动检查 id 是否重复。
- 自动检查 cover/gallery 引用的图片是否存在。

## 4. 标准维护流程

### 4.1 修改已有文档

1. 找到 `docs-vitepress/docs/xxx.md`。
2. 修改 frontmatter 的 `title/category/tags/updatedAt/summary`。
3. 修改正文 Markdown。
4. 图片放入 `public/images/docs/xxx/`。
5. 本地运行 `npm run dev`。
6. 构建：`npm run build`。
7. 部署。

### 4.2 新增技术文档

目标路径：

```text
docs-vitepress/docs/doc-id.md
public/images/docs/doc-id/
```

流程：

1. 新建 Markdown。
2. 填 frontmatter。
3. 写正文。
4. 如需图片，放入对应图片目录。
5. 本地预览。
6. 构建部署。

### 4.3 新增项目

目标路径：

```text
docs-vitepress/projects/project-id.md
public/images/projects/project-id/
```

流程：

1. 新建项目 Markdown。
2. 填写 `id/title/summary/stack/highlights/gallery/links/status`。
3. 准备封面、架构图、成果图。
4. 正文按项目案例模板写。
5. 本地预览。
6. 构建部署。

项目正文建议结构：

```markdown
# 项目标题

## 项目背景

## 项目目标

## 系统架构

## 技术栈

## 核心功能

## 难点与解决方案

## 成果展示

## 复盘总结
```

### 4.4 新增个人分享

目标路径：

```text
docs-vitepress/life/post-id.md
public/images/life/post-id/
```

流程：

1. 新建生活/摄影/成长记录 Markdown。
2. 填写 `id/title/date/tag/summary/cover/status`。
3. 放入图片。
4. 正文按图文记录写。
5. 本地预览。
6. 构建部署。

### 4.5 替换网站背景或个人头像

目标路径：

```text
public/images/site/
public/images/profile/
```

流程：

1. 放入语义化命名图片。
2. 修改 CSS 或页面配置引用。
3. 本地预览亮色/暗色模式。
4. 确认移动端不遮挡内容。

## 7. 验收标准

完成第一阶段内容治理后，应满足：

- 新增一篇技术文档，只需要新建 `.md` 文件。
- 新增一个项目，只需要新建 `.md` 文件并放图片。
- 新增一篇个人分享，只需要新建 `.md` 文件并放图片。
- 不需要在 `src/content/*.ts` 里手写长正文。
- `content/` 旧数据有明确去向，不再和主内容源混用。
- `public/` 图片能按用途找到。
- 乱码文档有明确修复或归档计划。
- 构建部署路径仍保持当前静态站方式：编辑内容 -> 本地预览 -> `npm run build` -> Pages 部署。
