# 项目叙事体验设计

日期：2026-07-28

## 已确认的目标

个人网站同时承担知识库、项目展示与个人表达。项目展示必须覆盖两种真实情况：

- 已完成项目：清楚地展示成果、效果、技术选择、实现过程与复盘。
- 持续更新项目：让访客看见当前进度、阶段成果、开放问题和下一步，而不把项目伪装成已经完成。

网站现有的整体框架、导航、宇宙/轨道/星空主题和普通文档阅读方式保持不变。创意集中在访客进入具体项目详情后的局部体验；项目详情是从同一个网站打开的一个空间，而不是另一个独立网站或游戏。

## 设计原则

1. 内容优先：Markdown、图片、GIF、视频、代码和链接必须在没有 WebGL、动画被关闭或设备性能不足时仍完整可读。
2. 互动有叙事职责：每个动效回答进入、推进、聚焦、发现或返回中的一个问题，不为了装饰而持续运动。
3. 普通路径零负担：新建项目默认使用成熟、可维护的案例模板，不要求准备 3D 素材或额外配置。
4. 局部自由：想做得更有趣时，单个项目可以启用沉浸模式并使用自己的视觉预设、场景素材或专用场景模块。
5. 全站一致：主题模式、返回逻辑、搜索、快捷操作、移动端行为和颜色语义不因项目而改变。

## 访客体验

### 默认项目

访客从项目列表卡片进入现有的项目详情壳。页面保留标题、摘要、技术栈、图集、亮点、链接和 Markdown 正文；卡片到详情的展开动画作为过渡，而不是强制性的沉浸开场。

默认项目适合已完成项目、素材较少的项目和不需要特殊叙事的项目。正文中的富文档区块仍是主要表达方式。

### 沉浸项目

沉浸项目采用以下稳定状态序列：

1. `card-preview`：项目卡片悬停时产生轻微纵深，展示项目阶段与最近更新。
2. `card-expanded`：点击后，卡片的封面、标题和状态展开到项目详情壳中；用户可短暂停留查看，再明确进入或返回。
3. `project-entry`：项目封面展示局部宇宙场景、项目标题、当前状态和阅读入口。鼠标或触摸只驱动轻微视差。
4. `chapter-travel`：滚动驱动章节前后景、轨迹高亮和证据浮现。正文没有被 Canvas 覆盖，用户可正常阅读、选择和复制内容。
5. `evidence-focus`：图片、GIF、视频、演示或代码片段可就地放大查看；关闭后回到原有阅读位置。
6. `return`：返回时以反向共享元素回到原项目卡片，恢复项目列表滚动位置。

轨迹不是独立仪表盘。它是沉浸项目的章节导航：已完成阶段使用金色，当前阶段使用青绿色，开放问题使用柔紫色，未来阶段保持低对比度。点击轨迹节点可跳转章节。

## 空间视觉语言

宇宙、轨道和星空是全站的共同语言，但不应压过内容：

- 远景：稀疏星点、网格、轨道和深层色块，只建立空间与层次。
- 中景：章节轨迹、阶段标记、环境光和视觉预设，表达时间与关系。
- 前景：标题、正文、图片、代码、视频和问题卡，始终保持可读与可操作。
- 已沉淀成果为金色，正在推进为青绿色，猜想与问题为柔紫色。

每个沉浸项目可选择一个视觉预设，例如 `orbit`、`signal` 或 `archive`。预设只改变局部场景中的几何、材质、图片层和动效参数；不改变网站全局排版、配色层级或交互控制。

需要完全个性化的项目可注册一个按项目 id 匹配的场景模块。该模块只接收标准化项目数据和声明的媒体资源，不能接管路由、全局快捷控件或正文渲染。

## 内容模型

现有项目 frontmatter 保留。新增字段全部可选，缺省值保证旧项目不受影响：

```yaml
presentation: standard # standard | immersive，默认 standard
narrative: chronicle # chronicle | field-notes | chapters，默认 chronicle
visualPreset: orbit # 仅 immersive：orbit | signal | archive
updatedAt: 2026-07-28
currentFocus: 把维护动作变成可见的叙事
```

叙事内容继续写在 Markdown 正文中。为持续更新项目新增可排序的语义区块，而非创建第二份项目数据：

```md
```milestone
date: 2026-07-28
title: 保存前差异预览
status: current
media: /images/projects/content-studio/diff-preview.gif
```
阶段说明与判断。

```question
title: 仍在思考
state: open
```
怎样让自由叙事保持长期可维护？

```next
title: 下一步
```
尝试可排序的项目叙事区块。
```

普通项目可完全不使用这些区块。沉浸项目按出现顺序将它们映射为章节、轨迹节点和前景证据；缺少语义区块时，仍把普通 Markdown 正文作为单一阅读章节。

内容工作台提供项目展示模式、叙事方式、视觉预设和当前焦点的基础字段。它允许插入、移动和预览语义区块，但不试图通过 GUI 生成任意 3D 场景。专属场景模块属于代码层能力，适用于少量确实值得定制的项目。

## 前端架构

新增一个项目展示解析层，将 `ProjectItem` 分为两个显式渲染策略：

- `StandardProjectExperience`：复用现有 `renderDocumentShell` 与项目详情信息。
- `ImmersiveProjectExperience`：复用同一详情壳和正文渲染器，在项目进入区、章节轨迹与证据查看区插入空间效果。

沉浸体验由以下独立单元构成：

- `ProjectTransition`：管理卡片展开、进入确认和原位返回。
- `ProjectScene`：可选 Three.js 局部 Canvas，只渲染封面与章节场景；根据 `visualPreset` 或项目模块选择内容。
- `NarrativeRail`：将语义区块映射为可点击轨迹，并同步滚动进度。
- `NarrativeChapter`：渲染一段 Markdown 与相关媒体，使用 CSS/GSAP 完成进入和离开。
- `EvidenceViewer`：复用或扩展现有图片/视频查看能力，保证焦点管理和关闭后位置恢复。
- `MotionPolicy`：集中判断减少动态效果、触摸设备和性能降级，不让业务组件自行猜测。

Three.js 只承载 `ProjectScene`，不接管文档 DOM。GSAP 的 ScrollTrigger 负责滚动进度、章节 pin 和同步；普通 CSS transform 承担卡片与文字的轻量变换。现有 `three` 与 `gsap` 依赖已满足，不在本阶段引入新的运行时库。

## 降级、性能与可访问性

- `presentation: immersive` 在禁用 WebGL、移动端能力不足或减少动态效果时自动回退为标准详情页加静态轨迹。
- Canvas 离屏、标签页不可见和退出详情时停止渲染循环；路由卸载时释放场景、纹理和 ScrollTrigger。
- Canvas 内部绘制分辨率设上限，按设备像素比和 viewport 计算，不盲目全分辨率渲染。
- 视频不自动播放有声音；所有项目内容有文本替代、键盘入口和明确的返回控制。
- 减少动态效果时移除大范围位移、视差和 scroll scrub，只保留淡入、轨迹状态与直接跳转。

## 实施边界

本项工作分为两个可独立交付的阶段：

1. 内容与默认项目：schema、模板、内容工作台字段、语义 Markdown 区块、普通项目兼容渲染和文档。
2. 沉浸体验：状态机、轨迹、过渡、性能策略、基础宇宙场景、视觉预设和一个示例沉浸项目。

专属项目场景模块在第二阶段建立接口后按需逐个增加；它们不是所有项目的必需能力。

不在范围内：重做网站首页、替换全局导航、把所有项目变成 3D、建设远程 CMS 或在线协作编辑器。

## 验收与验证

- 旧项目不写新字段时，构建、内容检查与现有详情页均正常。
- 工作台可创建并编辑默认项目与沉浸项目的基础字段，保存后差异预览仍正确。
- Markdown 语义区块可被校验、预览并按正文顺序渲染。
- 普通项目和沉浸项目均能从卡片进入并返回到原列表位置。
- 沉浸项目在桌面端具备可感知的进入、滚动、轨迹跳转和证据查看体验。
- 移动端、减少动态效果、WebGL 不可用时内容完整可读，且不会留下不可关闭的全屏层。
- 通过内容检查、类型检查、核心内容测试、生产构建，以及桌面/移动端的浏览器视觉验证。
