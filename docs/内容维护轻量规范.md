# 内容维护轻量规范

这份文件只放在本地，用来提醒后续怎么维护内容和素材，不接入网页导航。

## 目录约定

- 技术文档：`docs-vitepress/docs/*.md`
- 项目展示：`docs-vitepress/projects/*.md`
- 个人分享：`docs-vitepress/life/*.md`
- 图片素材：`public/images/docs`、`public/images/projects`、`public/images/life`

## 实时预览

开发服务器启动后，修改 Markdown 或样式会自动刷新页面。

```bash
npm run dev
```

如果只是新增图片但页面没有立刻显示，刷新浏览器即可。图片路径推荐写成：

```md
![截图](/images/projects/project-name/cover.png)
```

项目里已经处理了 `/embedded-blog/` base path，Markdown 里保持从 `/images/...` 开始即可。

## 卡片展示规则

- 项目卡片读取 `summary`、`stack`、`highlights`、`gallery`。
- 项目详情页会展示前 4 条 `highlights`。
- 文档卡片读取 `category`、`level`、`updatedAt`、`readingTime`、`views`。
- 生活卡片优先读取 `cover`；没有封面时使用笔记预览占位。
- `links.href: "#"` 会被隐藏，填真实链接后才显示行动入口。

## 发布前检查

```bash
npm run check:content
npx tsc --noEmit
npm run build
```

## 一键同步到 gh-pages

`gh-pages` 分支只存放构建后的静态文件，例如 `index.html`、`assets` 和 `public` 图片，不存源码。

当前线上地址是：

```text
https://www223-arch.github.io/embedded-blog/
```

只发布当前网页构建：

```bash
npm run sync:gh-pages
```

提交当前源码分支后，同时推源码分支并发布网页：

```bash
npm run sync:all
```

`sync:all` 会先检查工作区是否干净。如果还有未提交改动，它会停止，避免源码分支和线上页面不一致。
